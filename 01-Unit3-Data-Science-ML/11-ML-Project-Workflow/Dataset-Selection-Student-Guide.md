# בחירת מאגר נתונים לפרויקט — מדריך לתלמידים

**מבוסס על:** המסמך *דרישות לחיפוש מאגר ואתרי חיפוש* והטבלה *בחירת מאגר לפרוייקט* שסיפק המורה. פרטי תלמידים וקישורי ההגשות האישיות בטבלת המקור **אינם מפורסמים** כאן.

## בדיקת התאמה לפני אישור
- [ ] 1,000 שורות לפחות לפי הקריטריון במסמך.
- [ ] 7 מאפיינים שימושיים לפחות (לא רק מזהה ועמודת מטרה).
- [ ] לפחות שני מאפיינים רציפים.
- [ ] לפחות שני מאפיינים קטגוריאליים/בדידים; אם אין, יש לבחון יצירתם כנדרש במסמך.
- [ ] משתנה מטרה מוגדר היטב: סיווג (לפחות שתי מחלקות) או רגרסיה רציפה.
- [ ] התפלגות התגיות ידועה; במקרה של חוסר איזון יש תוכנית הערכה מתאימה.
- [ ] CSV זמין להורדה, עם מקור ורישיון שימוש ברור.
- [ ] אין מידע אישי רגיש או שדות החושפים ישירות את התשובה.

## דגשים והמלצות דידקטיות למורה
- תחילה תנו לתלמיד למצוא **שאלה שאפשר למדוד**, ואז לחפש Dataset שמתאים לה.
- אל תאשרו מאגר רק לפי מספר שורות: בדקו התאמת היעד, זמינות CSV, מספר מאפיינים שימושיים ואיכות התיעוד.
- מאגר גדול מדי או מלוכלך מאוד עלול לגזול את כל זמן התלקיט; העדיפו מאגר שניתן לחקור ולבנות עליו מודל בתחום היכולת של התלמיד.
- מומלץ לאשר הצעת פרויקט רק לאחר שהסטודנט מציג `shape`, `info`, `value_counts` למטרה ושאלת חקר מנומקת.
- לתלמידים מתקשים — תנו רשימת מועמדים מראש; למצטיינים — דרשו בדיקה של Leakage, אי־איזון ושאלות של הטיה/רישוי.
- שמרו את טבלת המורה הכוללת שמות אישיים מחוץ למאגר ציבורי.
