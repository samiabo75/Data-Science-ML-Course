# מפגש 26 — פרספטרון: סכום משוקלל ולמידה מטעות
## סיפור המסגרת ושאלת הלמידה
במקום לחפש שכנים, ננסה גבול החלטה המבוסס על משקולות שמשתנות בעקבות טעויות בדוגמאות אימון.

## מה נלמד ומדוע
פרספטרון מחשב z=w·x+b וממיר אותו לתווית לפי סף. כאן נבחר הכלל שמופיע בשקף 3: תווית 1 כאשר z>=0, אחרת 0. עדכון משקולות ו־ bias תלוי בטעות ובקצב הלמידה. זהו אימון של מסווג ליניארי, שאינו פותר XOR במרחב המקורי.

## דוגמה פתורה קטנה
כאשר w=[0,0], b=0, x=[1,0], y=0 וקצב הלמידה 0.5, החיזוי הוא 1 והטעות −1. לאחר עדכון w=[−0.5,0] ו־ b=−0.5.

```python
import numpy as np
w = np.array([0., 0.])
b = 0.
x = np.array([1., 0.])
y = 0
z = np.dot(w, x) + b
predicted = 1 if z >= 0 else 0
error = y - predicted
w = w + 0.5 * error * x
b = b + 0.5 * error
print(w, b)
```

**פלט צפוי ופירוש: ** [-0.5  0. ] -0.5. זוהי דוגמה קטנה ומוצהרת; היא אינה ציון ביצוע של פרויקט אמיתי.

## הדרך לתרגול העצמאי
עוקבים אחר החלטה ועדכון אחד, ואז מסבירים תבנית אימון ותרגול OR. בכל החומרים החדשים משתמשים ב־>=0 באופן עקבי.
עבדו לפי הסדר: נסחו את השאלה, זהו נתונים ויחידות, בחרו כלי שכבר נלמד, כתבו ציפייה, הריצו והסבירו תוצאה ומגבלה. במשימה שאינה מובנת חוזרים למושג או לדוגמה, ולא מחפשים שורת קוד להעתקה.
